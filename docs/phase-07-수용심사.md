## 1. 인정하는 것

- **F5 — E2E ⓑ가 묵은 304를 찾았다.** 대사·재구축이 달을 바꿔도 `seq`·설정이 같으면 ETag가 같아 브라우저가 "정상" 본문을 되살렸다. 이것은 **내 설계 결함**이다(§7 v1.6 ETag `seq.sync.cfg`, Phase 3 승인 Q4 — "데이터는 seq로만 바뀐다"는 전제가 대사·재구축에서 깨진다, **DD-20**). 운영에서도 대사 뒤 다음 날까지 "확인 중"이 안 보일 수 있었다. 수정 경로도 맞다 — 같은 문장에 붙이면 `* 100`이 새 산술 스캔에, 조회 경로 저장소로 읽으면 `ApiLayerRulesTest`에 걸려 **규칙을 좁히지 않고 문장 하나를 옮긴 것**(§4.9 +1 문장).
- **F4 — 주입 S2가 기존 두 스캔을 통과했다.** 둘은 `*`·`/`·`%`만 본다. C2가 "둘 무변경"이라 했으니 둘은 두고 대사 범위에 **허용 목록 없는** 새 스캔(`+ -`·`LSUB`)을 둔 것이 맞다. 지시문 C2가 "차이 값 0"을 말하면서 뺄셈을 보는 스캔이 없다는 것을 몰랐다(DE-29).
- **F6 — "평문 스캔(트레이스 포함)"이 스팬을 본 적이 없었다**(메모리 내보내기는 파일이 없다)를 보고서를 쓰다 찾고, 덤프 파일 + 주입으로 닫은 것. 첫 판을 `verifyTestInputs`가 막아 디렉터리를 출력으로 선언한 것 — 규칙이 일했다.
- **F7 — Spring 기본 스케줄러 스레드 하나**: 회차(최대 15분 + 재구축) 동안 전 테넌트 폴링이 멈췄을 것이다. 지시문·계획 어디에도 없던 판단, 시험으로 고정(`ingestAndReconTicksHaveTheirOwnThreads`).
- **F1 — V8 `CHECK`의 NULL 통과**를 거부 사례 시험이 잡고 V8을 고치지 않고 V9로 한 것(규칙 6).
- **S11b·S13 둘째 판** — 키 단언이 먼저 잡아 값 스캔이 시험되지 않은 것, ⓑ가 F5로 이미 실패하던 밑에서는 주입 증거가 못 된다는 것을 가려 다시 넣은 것. 주입이 "실패했다"가 아니라 "**기대한 곳에서** 실패했다"여야 한다는 기준.
- `ReconRulesTest` 1,807 — 격자 1,296칸이 판정만이 아니라 **엔진 호출 수·머리 읽기 수**까지 신탁과 비교한다. `PortalMeters`가 **커밋 뒤에만** 센다(롤백된 DRIFT를 세지 않는다).
