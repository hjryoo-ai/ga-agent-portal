# 포털 Phase 6 계획 승인 (2026-10-24) — ga-agent-portal

## 판정: 승인. Q1~Q30 전부 권장안(Q1 = 금액 없음, Q25 = 알림 없음 — 기록만). 추가 지시 하나(§2 A), 계획 수정 불필요

읽은 것: `docs/phase-06-계획.md` 전문(Q1~Q30, P-1~P-23, ②~⑭). 돌이킬 수 없는 결정은 없다는 판단(계약 1.2.0 추가만, V7은 열·인덱스·`CHECK`·`DROP NOT NULL`, 공유 계약·엔진 무변경)에 동의한다.

## 1. 인정하는 것

- **P-4 — `if/then`은 생성 타입을 좁히지 못한다**는 것을 고정한 생성기(`openapi-typescript` 7.13.0)로 **두 형태를 실제로 생성해** 확인한 것. 지시문이 거꾸로 적었다(DE-25). `oneOf` + `discriminator`가 맞다.
- **Q1 — 알림에 금액을 넣지 않는다.** 지시문이 "검토"로 남긴 쪽을 택했고 이유가 정확하다: 여섯째 라벨이 생기지 않고, 지난 값이 지금 값처럼 읽히지 않으며(확정 뒤 정정·환수), 누출 면적이 준다. C10을 "템플릿·`params`에 금액 0"으로 바꾼 것도 맞다 — `params` 스키마에 `Won` 참조 0을 계약 시험으로.
- **P-1 — 세 이벤트에 `agentId`가 없다**(`LimitLedgerPosted`·`LimitLedgerRebased`·`DeferralStatusChanged`). 뷰 행의 `agent_id`도 개설·예정 이벤트의 엔진 사실이라는 근거로 지시문 ①을 바로잡았다.
- **P-9 — 세 스트림에 규칙을 손으로 돌려** 기대 알림을 셌다: A-1 seq 8 `POLICY_CANCEL`(지시문 누락), seq 5가 OK → FULL로 두 경계를 한 번에 넘는 실례(Q2), GA04에 재산정이 없다는 사실. E2E 기대값이 추측이 아니다.
- **Q25 — 재구축이 처음 적용한 사실의 알림 공백**을 C3의 대가로 명시한 것. 숨기지 않고 보고서·Phase 7 질문으로 남긴다.
- **Q16 — 지금 코드는 파생 예외가 `PROJECTOR_ERROR` + `FAILED` 행**이라는 것을 읽고, 호출을 `try` 밖·같은 트랜잭션 안으로 옮겨 `APPLY_ERROR`(행 없음·전체 롤백)로 맞춘 것.
- **Q22·Q23** — 알림·문의는 `seq`와 무관하게 바뀌므로 뷰 ETag 재료가 맞지 않는다는 판단, 본문이 나오는 응답을 **하나**로 좁혀 C7의 닫힌 목록을 응답 하나 + CLI `list`로 만든 것.
- **Q9** — CLI를 같은 JVM에서 부르지 않고 자식 프로세스로 띄워 행위자(`user.name`)·출력 규약을 시험이 흉내 내지 않게 한 것. 자식 표준 출력은 버린다.
- **Q27** — "1,000자"를 코드 포인트로 정하고 화면이 `[...s].length`로 세는 것(UTF-16 `length`는 이모지에서 갈린다).

### A. 추가 지시 — 화면은 서버의 `link`를 닫힌 경로 목록에 대조한 뒤에만 이동한다

`link`는 서버 데이터다(계약 `pattern` + V7 `CHECK`가 있어도 화면은 입력을 믿지 않는다 — 규칙 8의 화면판). 화면은 `link`를 `ROUTE_PATHS`의 패턴(`/lines/:calcId`·`/limits/:ledgerId`·`/statements/:ym`·`/inquiries/:id`)에 **대조해 맞는 것만** 라우터에 넘기고, 맞지 않으면 `link` 없는 알림과 같게(읽음만) 처리한다. Vitest 하나(맞는 넷·틀린 셋 — 밖 출처 URL·`//`·모르는 경로)와 주입 S15(대조 제거 → 실패). 계획 ⑧에 한 줄, C10에 한 칸. 계획 재제출은 필요 없다.
